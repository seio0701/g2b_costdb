## 2. 전체 파이프라인 한눈에 보기

```
① collect   나라장터 API 전량 수집(월별)            → 공사 공고 1,294,182건 / 기초금액 1,025,708건
② discover  키워드로 시설 후보 탐색·시설명 정제      → 시설 후보 4,084개 (facility_candidates.xlsx)
③ 검수      사람이 Excel 에서 포함/제외 결정          → 포함 1,847 / 제외 1,808 / 검토필요 429 (기본값)
④ research  검수 통과 시설명으로 공고 재검색          → 공고 6,718건 (시설 1,836개)
⑤ dedup     차수·재공고·취소 정리, 프로젝트 묶기     → 대표 공고 4,214행 (고유 공고 3,834건, 프로젝트 1,978개)
⑥ attach    첨부 다운로드·텍스트 추출                → 텍스트 확보 3,821 / 3,834 공고 (99.7%)
⑦ extract   Claude API 로 공사개요·금액 구조화 추출  → 성공 3,573 / 실패 210 (2026-09-12 기준, 실패분 재제출 예정)
⑧ 교차검증  API 값 vs 문서 추출값 비교               → 검증로그 23,087건
⑨ excel     Excel DB 생성(수식 포함)                 → 공사비DB.xlsx (프로젝트 1,978개)
```

각 단계는 독립적으로 재실행할 수 있고, 원본 수집 파일(`data/raw/*.jsonl`)은 절대 덮어쓰지 않는다.

## 3. 단계별 상세

### 3.1 수집(collect)
- 공공데이터포털 API 를 **월 단위(2019-01 ~ 2026-09)** 로 호출해 공사 공고 목록과 기초금액 목록을 전량 내려받았다(페이지당 999건).
- 결과: 공고 **1,294,182건**, 기초금액 **1,025,708건**. 시험 수집 때 추정(월 8,800건)보다 많은 월평균 약 14,000건.
- 운영 규칙: 일일 호출 예산 950회(개발계정 1,000회/일), 재시도 5회, 원본 응답은 `data/raw/*.jsonl` 로 보존하고 파케이(parquet)로 변환해 사용.
- 낙찰정보서비스(낙찰금액·낙찰률·낙찰자) 연동 코드는 완성했으나 **활용신청 승인 대기 중이라 아직 미연동**(설정 `use_awards: false`).

### 3.2 시설 후보 탐색(discover)
- 129만 건 공고명을 키워드 사전(`keywords.yaml`)으로 걸러 시설 후보를 뽑는다. 분류별 포함어·제외어, 공통 제외어(도로·상하수도·궤도·가로등 등)를 둔다.
- 공고명에서 괄호·상태어(입찰·공고·제출·안내 등)·연도 접두어(′23∼′24년 등)·공종어를 제거해 **시설명**을 만들고, 같은 시설명+수요기관을 하나의 시설(시설ID)로 묶는다.
- **사업유형**은 공고명 규칙으로 판정한다: 리모델링(리모델링·개보수·개축·대수선·현대화 등) → 증축(증축·별관·확충·증설) → 신축(신축·건립·건설·조성) 순으로 우선 적용, 유지보수 어휘(보수·방수·도색·교체·정비 등)만 있으면 유지보수로 보아 기본 제외.
- 단지명이 없는 일반 명칭(예: "공공주택")은 **수요기관(지자체)명을 접두**해 구분한다(사용자 요청 반영).
- 후보 파일은 4,148 → 4,037 → 4,132 → **4,084개 시설**로 규칙을 보강하며 재생성했고, 검수 기본값은 포함 1,847 / 제외 1,808 / 검토필요 429 였다. 재생성 때 사용자가 고친 검수값만 이어받도록 했다.

### 3.3 사람 검수
- `output/facility_candidates.xlsx` 에서 사용자가 **포함/제외/검토필요**, 별칭, 메모를 결정한다. Claude 는 검수 셀을 채우지 않는다.
- 같은 시설이 수요기관만 달라 둘로 잡힌 경우(예: 도시공사 vs 시청)는 검수에서 **시설ID 를 같게 적으면** 다음 단계에서 한 시설로 병합된다.

### 3.4 재검색(research)
- 검수 통과 시설의 시설명·별칭으로 전량 공고를 다시 찾아 그 시설의 **모든 공종 공고(건축·전기·정보통신·소방·조경·기계설비·토목·기타)** 를 모은다.
- 정확한 이름으로 못 찾으면 어절 사이 간격을 허용한 **예비 검색**으로 보완(54개 시설 회복). 결과 **6,718건(시설 1,836개)**.

### 3.5 중복·재발주 정리(dedup)
- **프로젝트키 = (시설ID, 사업유형, 공종[, 단계토큰])**. 같은 시설의 신축과 리모델링은 별도 프로젝트, 1단계/2공구 같은 분할발주도 별도.
- 규칙: ① 공종 공고의 사업유형이 없으면 같은 시설의 가장 가까운 건축 공고에서 상속 ② 같은 공고번호는 최대 차수(변경공고) 채택 ③ 취소공고 제외 후 프로젝트키별 **최신 공고 1건을 대표**로 채택(재공고·재발주 처리) ④ 추정가격이 프로젝트 내 최대치의 30% 미만인 공고는 부대공사로 보아 대표에서 제외(경고 기록) ⑤ 대체 전후 추정가격 변동 ±30% 초과는 설계변경 의심 경고.
- 결과: 대표 **4,214행**(고유 공고 3,834건, 프로젝트 **1,978개**). 대표 행 중 **347행은 같은 공고가 두 시설에 배정된 복합 발주**로, 검증로그에 "복수 시설 배정"으로 기록해 검수 대상으로 남겼다.
- 프로젝트ID = 시설ID-사업유형코드(N 신축 / E 증축 / R 리모델링 / ER 증축·리모델링).

### 3.6 첨부 다운로드·텍스트 추출(attach)
- 공고당 첨부를 우선순위(공고문 > 현장설명서·설계설명서 > 관급자재 > 내역서 > 시방·과업)로 최대 4개 내려받아 텍스트를 뽑는다. HWP(자체 파서 → pyhwp → 한컴 COM 폴백), HWPX, PDF(pdfplumber, 스캔본은 OCR 선택), DOCX, XLSX, ZIP(내부 파일 6개까지) 지원. 도면(dwg)·이미지는 제외.
- 문제와 해결: HWP 의 서로게이트 문자 때문에 텍스트 저장이 실패해 209건이 "성공인데 텍스트 없음"으로 남았던 것을 파서·저장 로직 수정으로 복구. 대표 공고가 정정·변경 차수라 짧은 정정공고서만 있는 경우는 **같은 공고번호의 다른 차수 첨부를 합쳐**(234건) 처리.
- 결과: **3,821 / 3,834 공고에서 텍스트 확보(99.7%)**. 남은 13건은 첨부 없음·이미지뿐인 파일 등 원천 한계. 첨부 전량 다운로드에 약 3.6시간 소요.

### 3.7 LLM 구조화 추출(extract)
- 모델 `claude-sonnet-5`, 공고당 입력 최대 60,000자(앞부분 + "공사개요·연면적·추정가격·관급" 등 키워드 주변 발췌), JSON 스키마 강제(구조화 출력).
- 추출 항목(23개): 공사명, 용도, 사업유형, 연면적_m2, 건축면적_m2, 대지면적_m2, 지하층수, 지상층수, 구조, 공사기간_일, 추정가격_원, 기초금액_원, 부가가치세_원, 도급자관급액_원, 관급자관급액_원, 총공사금액_원, 설계금액_원, 공종, 신뢰도(high/medium/low), 근거문구(항목별 원문 인용) 등. **금액·면적은 문서 본문에 적힌 값만** 추출하고 없으면 비운다(API 메타데이터는 식별용).
- 시범 40건은 Cowork(파일 인수인계 방식)로, 이후 15건은 API 즉시 호출로 검증한 뒤 **Message Batches(50% 할인)** 로 본 추출: 3,783건 제출, 8개 배치, 견적 약 $96.77.
- 결과(2026-09-12 기준): **성공 3,573 / 실패 210**. 누적 토큰 입력 8,962만·출력 800만(공고당 평균 입력 약 22,500·출력 약 2,000 토큰). 토큰 사용량으로 환산한 실제 비용은 약 $130 수준으로 추정(견적이 출력 토큰을 적게 잡았음. 정확한 청구액은 콘솔에서 확인).
- 실패 210건 원인: 161건은 모델의 사고(thinking) 토큰이 출력 한도(8,000)를 소진해 JSON 이 나오기 전에 잘림, 22건은 API 측 오류. 조치: 출력 한도 16,000 으로 상향, 잘린 건은 2배(32,000)로 자동 재요청. **재제출 예정이며 결과 반영 시 성공 건수가 늘어난다.**

### 3.8 교차검증(06_검증로그)
API 값과 문서 추출값을 공고마다 비교해 판정(정상/참고/경고/오류/미확인)을 남긴다.

| 항목 | 규칙 | 판정 |
|---|---|---|
| 추정가격, 기초금액 | 문서값 vs API값 차이율 | ≤0.5% 정상 / ≤5% 경고 / 초과 오류. 한쪽만 있으면 참고, 둘 다 없으면 미확인 |
| 기초금액≈추정가격×1.1 | 기초금액이 추정가격의 1.1배인지 | ±1% 이내 정상, 초과 경고("부가세 비율 불일치(면세·관급 포함 여부 확인)") |
| 사업유형 일치 | 공고명 규칙 분류 vs 문서 판독 | 다르면 경고(프로젝트 분리 확인) |
| 연면적 범위 / 층수 범위 | 50㎡ 미만·50만㎡ 초과 / 지상 60층 초과 | 경고(단위 혼동·오독 의심) |
| 도급자관급액, 관급자관급액 | 문서값 vs API값 | ±1% 정상, 초과 경고(API 우선 사용), 한쪽만 있으면 참고 |
| 총공사금액=기초금액+관급 | 문서의 총공사금액 vs 기초금액+관급 합 | ±1% 정상, 초과 경고 |
| 소액 공고 분리, 재발주 금액변동 | dedup 규칙 ④⑤ | 경고 |
| 복수 시설 배정 | 한 공고가 두 시설에 배정 | 검수 필요 표시 |

결과(2026-09-12 기준, 23,087건): 정상 16,375 / 경고 3,437 / 참고 2,844 / 오류 55(기초금액 41·추정가격 14) / 미확인 29 / 복수 시설 배정 347.
경고 상위: 총공사금액=기초금액+관급 1,049, 소액 공고 분리 587, 사업유형 일치 513, 재발주 금액변동 442, 기초금액≈추정가격×1.1 393.

## 4. 총공사비 산정 방식 (핵심)

### 4.1 원칙
1. 공사비의 기준은 **기초금액(추정가격 + 부가세 10%)** 이다. 이는 예정가격 산정의 기준 금액이며 발주처가 공고에 명시한 값이다.
2. **낙찰금액은 쓰지 않는다.** 낙찰가는 경쟁 결과(낙찰률 80%대)에 따라 달라지므로 "이 시설을 짓는 데 드는 비용"의 기준으로 부적절하다. 참고 컬럼으로만 둔다.
3. **관급자재는 별도로 더한다.** 기초금액에는 발주처가 직접 사는 관급자재(철근·레미콘·승강기 등)가 빠져 있으므로, 시설의 총공사비에는 관급자재 금액을 합산해야 한다.
4. 값의 출처는 **API 값 우선, 없으면 문서(공고문) 추출값**. API 값은 발주처가 시스템에 입력한 정형 데이터라 신뢰도가 높고, 문서 추출값은 LLM 판독이라 보조로 쓴다.
5. 시설의 총공사비는 **공종별(건축·전기·정보통신·소방·조경·기계설비·토목·기타) 대표 공고의 총공사비를 합산**한 것이다. 분리 발주된 전기·소방 등을 빠뜨리면 과소 계상되므로 공종 누락을 경고한다.

### 4.2 04 시트 「총공사비(수식)」 — 공고 1건의 총공사비

```
총공사비 = 기본금액 + 관급자재금액

기본금액(우선순위 순, 처음 있는 값 채택)
  1) 기초금액_API
  2) 추정가격_API × 1.1          (기초금액 API 값이 없을 때, 부가세 10% 가산)
  3) 기초금액_문서               (API 에 둘 다 없을 때 공고문에서 읽은 값)
  4) 추정가격_문서 × 1.1
  5) 0                           (아무 값도 없음 → 05 시트에서 "금액없음" 경고)

관급자재금액(우선순위 순)
  1) 도급자관급액_API + 관급자관급액_API   (둘의 합이 0 보다 크면)
  2) 관급자재_API                          (합계 필드만 있는 경우)
  3) 도급자관급액_문서 + 관급자관급액_문서  (API 에 없으면 공고문 추출값)
```

실제 셀 수식(행 r, 열 문자는 시트 배치에 따라 다름):
```
=IF(ISNUMBER(기초금액_API), 기초금액_API,
   IF(ISNUMBER(추정가격_API), 추정가격_API*1.1,
      IF(ISNUMBER(기초금액_문서), 기초금액_문서,
         IF(ISNUMBER(추정가격_문서), 추정가격_문서*1.1, 0))))
+ IF(N(도급자관급액_API)+N(관급자관급액_API)>0, N(도급자관급액_API)+N(관급자관급액_API),
     IF(N(관급자재_API)>0, N(관급자재_API), N(도급자관급액_문서)+N(관급자관급액_문서)))
```
`N()` 은 빈 셀을 0 으로 취급하는 함수다.

**계산 예시**

| 경우 | 입력값 | 총공사비 |
|---|---|---|
| A. API 값이 모두 있음 | 기초금액_API 11,000,000,000 / 도급자관급액_API 500,000,000 / 관급자관급액_API 300,000,000 | 11,000,000,000 + 800,000,000 = **11,800,000,000** |
| B. 기초금액 API 없음 | 추정가격_API 10,000,000,000 / 관급자재_API 700,000,000 | 10,000,000,000×1.1 + 700,000,000 = **11,700,000,000** |
| C. API 금액 없음(문서만) | 기초금액_문서 2,200,000,000 / 관급 없음 | **2,200,000,000** |
| D. 아무 값도 없음 | - | **0** (05 시트 "금액없음" 경고) |

용어: **도급자관급액** = 관급자재 중 시공사(도급자)가 설치하는 자재 금액, **관급자관급액** = 발주처(관급자)가 직접 설치하는 자재 금액. 나라장터 공고에는 이 둘과 합계(관급자재금액)가 따로 있다.

### 4.3 04 시트의 보조 수식
- **부가세(수식)** = 기초금액 − 추정가격 (API 값 우선, 없으면 문서값). 부가세 면제 사업이면 0 에 가깝다.
- **추정가격_차이율(수식)** = (추정가격_문서 − 추정가격_API) / 추정가격_API. LLM 판독 오류 점검용.
- **낙찰률(수식)** = 낙찰금액_API / 기초금액_API. API 의 낙찰률과 대조용(참고).

### 4.4 05 시트 — 프로젝트(시설×사업유형) 단위 합산과 ㎡당 공사비

```
공종별 금액(수식)     = SUMIFS(04!총공사비, 04!프로젝트ID = 이 행, 04!공종 = "건축")   … 공종 8개 각각
총공사비합계(수식)     = 공종별 금액 8개의 합
연면적_m2             = 01_시설마스터의 연면적을 INDEX/MATCH 로 참조 (01 에서 고치면 자동 반영)
㎡당공사비_원(수식)    = 총공사비합계 / 연면적   (연면적이 없거나 0 이면 빈 칸)
건설공사비지수_보정계수(입력) = 사용자 입력(기본 1.0). 기준연도 지수 / 공고연도 지수
보정_㎡당공사비_원(수식) = ㎡당공사비 × 보정계수
공종누락경고(수식)     = 건축·전기·정보통신·소방 중 공고가 없으면 "○○ 누락", 공고는 있는데 금액이 0 이면 "○○ 금액없음"
```

- 한 프로젝트에 같은 공종의 대표 공고가 여러 개(분할발주 등)면 SUMIFS 가 모두 합산한다.
- 시점 보정은 자동 계산하지 않고 **보정계수를 사용자가 입력**하도록 두었다(건설공사비지수 등 기준 선택은 연구자의 판단).

### 4.5 비교 시 주의
- **㎡당 공사비는 사업유형이 같은 프로젝트끼리만 비교**한다. 리모델링의 연면적은 공사 대상 면적이라 신축과 직접 비교할 수 없다.
- 복합 발주(한 공고가 두 시설)는 06 시트 "복수 시설 배정"에 표시되며, 검수 없이 합산하면 두 시설에 이중 계상될 수 있다.
- 부가세 면제 사업(공공주택 등)은 기초금액 = 추정가격이므로 2)·4) 경로(×1.1)가 적용되면 과대 계상된다. 현재는 API 기초금액이 있으면 그대로 쓰므로 대부분 문제없으나, 문서값만 있는 경우를 위해 규칙 보완 예정.

### 4.6 산식은 나중에 바꿀 수 있다
원천값(파란 글자)은 그대로 두고 수식(검은 글자)만 바꾸면 되므로, 예컨대 "총공사비(관급 제외)" 컬럼을 추가하거나 부가세 처리를 바꾸는 일은 Excel 생성 코드의 수식 한 줄을 고쳐 재생성하면 된다.

## 7. 부록

### 7.1 용어
- **추정가격**: 부가세를 뺀 공사 예상 금액(국가계약법). 입찰 방식 결정 기준.
- **기초금액**: 추정가격 + 부가세. 예정가격 산정의 기준. 나라장터 공고에 표시.
- **예정가격**: 기초금액에 복수예비가격을 적용해 개찰 시 결정되는 낙찰 상한. 본 DB 에서는 사용하지 않음.
- **관급자재**: 발주처가 직접 구매해 공급하는 자재. 도급자설치분과 관급자설치분으로 나뉨.
- **차수(공고차수)**: 같은 공고번호의 변경·정정 회차(000, 001, …). 최대 차수를 채택.
- **재공고·재발주**: 유찰 등으로 다시 낸 공고. 프로젝트키가 같으면 최신 1건만 대표.
- **대표 공고**: 프로젝트키(시설, 사업유형, 공종)별로 채택한 1건. 04 시트의 행 단위.
