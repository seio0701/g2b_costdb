# 나라장터 발주공고 기반 LIMAC 공사비 DB 구축 — 자동화 울트라 플랜

- 작성일: 2026-09-05
- 대상: 「자체타당성조사 공사비 DB 작업 관련 자료」 표2의 시설용도(문화예술회관·미술관·수장고·공공주택·경기장·주차장·화장시설·야외음악당·호텔·축산시험장·온실·재난물자창고)
- 산출물: `공사비DB.xlsx` (시설마스터 / 공고목록 / 공종별 공사비 / 시설합산 / 검증로그) + 재실행 가능한 Python 파이프라인(`g2b_costdb/`)

## 0. 결론 요약

□ 나라장터는 **공고 메타데이터·금액·첨부파일 URL까지는 Open API로 제공**하나, **공고문 파일 안의 내용(연면적·층수·구조·관급자재 등)은 API로 제공하지 않음**
  ㅇ 공공데이터포털 「조달청_나라장터 입찰공고정보서비스」(`apis.data.go.kr/1230000/ad/BidPublicInfoService`)에서 공사 공고목록·기초금액·면허제한·변경이력 조회 가능(월 단위 기간조회, 페이지당 최대 999건)
  ㅇ 공고 응답에 첨부파일 URL(`ntceSpecDocUrl1~10`)·파일명(`ntceSpecFileNm1~10`)이 포함되어 HWP/PDF 공고문을 직접 내려받을 수 있음
  ㅇ 따라서 "API로 목록·금액 수집 → 첨부파일 다운로드 → HWP/PDF 텍스트 추출 → LLM 구조화 추출 → API 값과 교차검증 → Excel DB" 흐름으로 자동화 가능함

□ 검색 전략은 제안하신 2단계(광역 키워드 → 시설명 재검색)를 채택하되, **API 호출을 시설명마다 반복하지 않고 "기간별 공사 공고 전량 1회 수집 → 로컬(pandas)에서 키워드·시설명 검색"** 방식으로 바꾸는 것이 유리함
  ㅇ 개발계정 일일 트래픽이 1,000건이므로 키워드×월 반복 호출(약 30개 검색어 × 93개월 ≈ 2,800회)은 비효율적임
  ㅇ 전량 수집은 93개월 × 월 3~6페이지 ≈ 500회 내외로 1~2일이면 완료되고, 이후 재검색·재분류는 API 없이 무한 반복 가능함

□ 재발주(변경·재공고) 처리는 (시설 + 사업유형 + 공종)을 프로젝트키로 묶어 **취소공고를 제외한 최신 공고 1건만 대표값**으로 채택하고, 나머지는 이력 시트에 보존함
  ㅇ 신축·증축·리모델링을 모두 DB 대상으로 하되, 같은 시설의 신축과 리모델링은 **별도 프로젝트(프로젝트ID = 시설ID-N/E/R/ER)** 로 분리 집계함(유지보수성 공사만 제외)

□ 공사비 DB의 금액 기준은 첨부 자료의 유의사항대로 **낙찰가가 아닌 추정가격·기초금액(예정가격 산정 기준)**이며, 공종별 분리발주 합산 + 관급자재 별도 계상 + 부가세 구분을 구조적으로 강제함

## 1. 데이터 소스 검토: API로 무엇이 되고 무엇이 안 되는가

### 1-1. Open API로 제공되는 것 (조달청_나라장터 입찰공고정보서비스, data.go.kr/data/15129394)

| 구분 | 오퍼레이션 | 핵심 파라미터 | 핵심 응답필드 | 용도 |

| 공사 공고목록(기간) | `getBidPblancListInfoCnstwk` | `inqryDiv=1`, `inqryBgnDt/EndDt`(YYYYMMDDHHMM, 최대 1개월) | `bidNtceNo`, `bidNtceOrd`, `bidNtceNm`, `ntceKindNm`, `reNtceYn`, `bidNtceDt`, `dminsttNm`, `ntceInsttNm`, `presmptPrce`, `mainCnsttyNm`, `cnstrtsiteRgnNm`, `bidNtceDtlUrl`, `ntceSpecDocUrl1~10`, `ntceSpecFileNm1~10` | **전량 수집(권장 경로)** |

| 면허제한(업종) | `getBidPblancListInfoLicenseLimit` | `bidNtceNo` | `indstrytyNm`(건축공사업/전기공사업/정보통신공사업/소방시설공사업/조경공사업 등) | **공종 분류 근거** |
| 변경이력 | `getBidPblancListInfoChgHstryCnstwk` | `bidNtceNo` | 변경일시·변경사유 | 재공고 추적 |
| (선택) 낙찰정보 | 낙찰정보서비스 `getScsbidListSttusCnstwk…` | 기간/공고번호 | 낙찰금액·낙찰률 | 참고 컬럼(DB 기준값은 아님) |

- 인증: 공공데이터포털 회원가입 → 「조달청_나라장터 입찰공고정보서비스」 활용신청(자동승인) → 일반 인증키(Decoding) 사용
- 트래픽: 개발계정 1,000회/일 → **활용사례 등록 후 운영계정 트래픽 증설을 초기에 신청**할 것
- 유의: 포털 메타데이터의 "시간범위 ~2025년 1월" 표기는 차세대 나라장터(2025.1) 전환 전 등록정보로, `…/1230000/ad/…` 경로가 현재 데이터를 제공함(2026년 공고 조회 사례 확인). 실제 응답 필드명은 활용가이드(참고문서 `…입찰공고정보서비스_1.2.docx`)로 최종 확인하고, 코드는 미존재 필드를 무시하도록 설계함

### 1-2. API로 제공되지 않는 것 → 첨부파일 파싱으로 보완

| 필요 항목 | API 제공 | 확보 경로 |
|---|---|---|
| 추정가격 | O (`presmptPrce`) | API 우선, 공고문으로 교차검증 |
| 기초금액(추정가격+VAT) | O (기초금액 오퍼레이션 `bssamt`) | API 우선 |
| 도급자 관급액 / 관급자 관급액(관급자재대) | X | 공고문 "공사금액 구성" 표, 관급자재내역서(xlsx) |
| 연면적·건축면적·층수·구조·용도 | X | 공고문 "공사개요", 현장설명서, 설계설명서 |
| 공사기간(착공~준공, 일/개월) | X | 공고문 |
| 공종(건축/전기/정보통신/소방/조경) | 간접(면허제한 업종, 주공종명) | API 업종 + 공고명 규칙 + 공고문 |
| 사업유형(신축/증축/리모델링/유지보수) | X | 공고명 규칙 + LLM 판별 |

### 1-3. 나라장터 외 보완 소스(표2 항목 중 누락 위험)

- 공공주택·행복주택·공공실버주택: LH 발주분은 **LH 전자조달(ebid.lh.or.kr)** 에 게시되어 나라장터 API에 미포착될 수 있음 → SH·GH 등 지방공사 발주분(나라장터 게시)을 우선 수집하고 LH분은 별도 수집 여부를 판단
- 국방·군 시설(D2B), 한전(KEPCO e-bid) 등 자체 조달시스템도 동일 → 표2 시설은 대부분 지자체 발주이므로 영향은 제한적

## 3. 파이프라인 아키텍처 (7단계)

```
[S0 설정] keywords.yaml(표2) + config.yaml(API키, 기간 2019.01~2026.09, 모델)
    │
[S1 전량수집]  getBidPblancListInfoCnstwk 월단위 × 페이지(999) → raw/notices_*.jsonl → SQLite(cache)
    │            + getBidPblancListInfoCnstwkBsisAmount 월단위 → 기초금액 병합
    │
[S2 광역탐색]  로컬 검색: 공고명 ⊃ 검색어(미술관, 문화예술회관…) → 후보 공고
    │            시설명 추출(규칙 → LLM 보조) + 사업유형 분류(신축/증축/리모델링/유지보수)
    │            → facility_candidates.xlsx  ★ 사람 검수(포함/제외, 시설명 수정)
    │
[S3 시설재검색] 검수된 시설명으로 로컬 재검색 → 공종별(건축·전기·정보통신·소방·조경) 공고 전부 수집
    │            + getBidPblancListInfoLicenseLimit(공고번호별) → 업종 → 공종 확정
    │
[S4 중복정리]  프로젝트키 = (수요기관, 시설명, 공종) / 취소 제외 / 차수·재공고 중 최신 1건 대표
    │            → notices_latest.parquet (+ 이력 보존)
    │
[S5 첨부수집]  최신 공고의 첨부 URL 다운로드(공고문·현장설명서·관급자재내역 우선) → 텍스트 추출
    │            HWP(olefile+zlib 레코드 파서 / pyhwp / 한컴 COM) · HWPX(XML) · PDF(pdfplumber, 스캔은 OCR) · XLSX · ZIP
    │
[S6 LLM추출]   Claude API에 JSON 스키마로 공사개요·금액구성 추출 → API 값과 Python 교차검증 → 검증로그
    │
[S7 Excel]     openpyxl로 7개 시트 생성(수식 포함) → 공사비DB.xlsx
```

### S1. 전량 수집 (핵심 설계 변경)
- 월 단위(`inqryBgnDt=YYYYMM010000`, `inqryEndDt=YYYYMM말일2359`) × `numOfRows=999` 페이지네이션, `totalCount`로 종료 판정
- 모든 응답을 원문 JSONL로 저장(필드 누락 방지) + SQLite 캐시로 재호출 방지(키: 오퍼레이션+파라미터 해시)
- 재시도: 오류코드 22/23(트래픽 초과)·05(타임아웃)에 지수 백오프, 일일 한도 도달 시 다음 날 재개(체크포인트 파일)
- 예상 호출량: 93개월 × (공고 4~6페이지 + 기초금액 4~6페이지) ≈ 800~1,100회 → 개발계정 기준 1~2일

### S2. 광역 탐색 + 시설명 추출
- 검색어는 표2 그대로 사용하되 변형어 추가(예: 미술관 → 미술관·아트뮤지엄·미술박물관 / 화장시설 → 화장장·추모공원·승화원 / 봉안당 → 봉안시설·봉안묘·추모관)
- 시설명 규칙 추출: 공고명에서 검색어를 포함하는 어절과 그 앞 어절(지자체명·수식어)을 묶음 → "수원시립미술관", "고흥군 문화예술회관"; 공종어·상태어("건립공사", "전기공사", "(재공고)", "(긴급)", "[변경]") 제거
- 사업유형 판별(규칙, 우선순위 순): 리모델링·개보수·개축·재건축·대수선 → **리모델링**; 증축·별관 → 증축(리모델링 어휘 동반 시 **증축·리모델링**); 신축·건립·건설·조성 → **신축**; 보수·방수·도색·교체·유지·철거·정비 → 유지보수(**DB 제외 기본값**). 신축·증축·리모델링은 모두 DB 대상
- 공종 공고의 사업유형이 미분류(예: 'OO미술관 전기공사')이면 같은 시설에서 공고일이 가장 가까운(±2년) 건축 공고의 사업유형을 상속
- 규칙 실패·애매 건은 LLM(배치 200건)으로 시설명·사업유형 보조 판별 후 `facility_candidates.xlsx`에서 사람이 최종 검수(포함/제외 체크, 시설명 수정)

### S3. 시설명 재검색 + 공종 확정
- 검수된 시설명(+ 별칭)으로 로컬 전량 데이터를 다시 검색 → 공고명에 검색어가 없는 분리발주(예: "○○미술관 건립 정보통신공사")까지 포착
- 공종 분류 우선순위: ① 면허제한 업종명 → ② `mainCnsttyNm`(주공종명) → ③ 공고명 정규식(전기/정보통신·통신/소방/조경/기계설비/토목/건축·건립·신축)
- 면허제한 API는 공고번호별 호출이므로 최신 공고(S4 이후)만 조회하여 호출량 절약

### S4. 중복·재발주 정리 (요청사항 반영)
- 1차: 동일 공고번호의 차수(`bidNtceOrd`)가 여러 개 → 최대 차수(변경공고) 채택
- 프로젝트키 = (시설ID, 사업유형, 공종, 단계토큰). 같은 시설의 신축(2019)과 리모델링(2025)은 서로 다른 프로젝트이므로 합쳐지지 않음
- 2차: 동일 프로젝트키에 서로 다른 공고번호(유찰 후 재공고, 취소 후 재발주, 설계변경 재발주) → `ntceKindNm`에 '취소' 포함 건 제외 후 `bidNtceDt` 최신 1건 채택, 나머지는 `대체됨` 표시 + 대체 공고번호 기록
- 분할발주 보호: 시설명 정규화 시 "1단계/2단계/1차/2차/○공구/골조/마감" 토큰은 보존하여 별개 프로젝트로 유지
- 금액 급변 경고: 대체 전후 추정가격 차이 ±30% 초과 시 검증로그에 '설계변경 의심' 기록

### S5. 첨부파일 수집·텍스트 추출
- 파일 선별 우선순위: `공고문/입찰공고` > `현장설명서/공사설명서/설계설명서` > `관급자재/관급내역` > `내역서(xlsx)` > 기타; 도면(dwg)·zip 내 이미지는 제외
- HWP(5.0 바이너리): olefile로 BodyText/Section 스트림 → zlib(raw) 해제 → 레코드 파서로 HWPTAG_PARA_TEXT(0x43) 추출(표 셀 텍스트 포함). 실패 시 `hwp5txt`(pyhwp) → Windows에서는 한컴오피스 COM(`HWPFrame.HwpObject`)으로 TXT 변환 폴백. 배포용(DRM) HWP는 실패 로그 후 수동 처리
- HWPX: zip 내 `Contents/section*.xml`의 `<hp:t>` 텍스트 + 표 구조 유지
- PDF: pdfplumber(표 추출 포함) → 폰트 없음(스캔)이면 pytesseract OCR(kor)
- 추출 텍스트는 `text/<공고번호>_<파일명>.txt`로 저장(재추출 방지, 근거 확인용)

### S6. LLM 구조화 추출 + 교차검증
- 입력: 추출 텍스트 중 키워드(공사개요·규모·연면적·층수·구조·공사기간·추정가격·기초금액·관급·부가가치세) 주변 창을 우선 배치, 최대 약 60k자
- 출력(JSON): 공사명, 위치, 연면적, 건축면적, 지하/지상 층수, 구조, 용도, 공사기간(일/개월), 추정가격, 기초금액, 부가세, 도급자관급액, 관급자관급액, 총공사금액, 설계금액, 공종, 사업유형, 각 항목의 근거문구·신뢰도
- 교차검증(Python): 문서 추정가격·기초금액 vs API 값(차이율 0.5% 초과 → 경고), 기초금액 ≈ 추정가격×1.1(±1% 초과 → 경고), 연면적 단위(㎡/평) 혼동 체크, 층수 표기 정합성
- 모델: `claude-sonnet-5`(기본, config로 변경) — 대량 처리 시 Message Batches API로 비용 절감 가능. SDK 사용법·모델명은 https://docs.claude.com/en/api/overview 기준으로 확인

### S7. Excel DB 생성
- 수식 기반(총공사비·부가세·차이율·시설합산 SUMIFS·㎡당 공사비), 하드코딩 금지, 단위 헤더 명기, 검수 셀 노란색
- 생성 후 LibreOffice 재계산으로 수식 오류 0건 확인(`recalc`), 검증로그에 오류/경고 건수 요약 기재

## 5. 코드 구성 (`g2b_costdb/`)

```
g2b_costdb/
├── README.md                 실행 순서·환경설정
├── requirements.txt
├── config.yaml               API 키(환경변수), 기간, 경로, 모델, 임계값
├── keywords.yaml             표2 → 대분류/중분류/검색어/변형어/제외어
├── g2b_costdb/
│   ├── api_client.py         G2BClient: 호출·페이지네이션·월분할·재시도·SQLite 캐시
│   ├── collect.py            S1 전량수집(공고+기초금액), S3 면허제한 조회
│   ├── discover.py           S2 로컬 키워드 검색·시설명 추출·사업유형 분류·검수용 Excel
│   ├── classify.py           공종/사업유형/공고종류 규칙 분류
│   ├── dedup.py              S4 프로젝트키·최신공고 선별·이력
│   ├── attachments.py        S5 다운로드·HWP/HWPX/PDF/XLSX/ZIP 텍스트 추출
│   ├── extract_llm.py        S6 Claude 구조화 추출·교차검증
│   ├── build_excel.py        S7 Excel DB
│   └── pipeline.py           CLI: python -m g2b_costdb.pipeline <stage>
├── tests/test_dedup_and_excel.py   합성 데이터로 S4·S7 검증
└── sample_output/공사비DB_샘플.xlsx  합성 데이터 기준 스키마 예시
```

- 실행 순서: `collect` → `discover` → (Excel 검수) → `research` → `dedup` → `attach` → `extract` → `excel`
- 모든 단계는 중간 산출물(parquet/jsonl)을 남기며 단계 단위 재실행 가능
