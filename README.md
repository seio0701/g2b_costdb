# g2b_costdb — 나라장터 발주공고 → LIMAC 공사비 DB 파이프라인

표2 시설용도(미술관·문화예술회관·수장고·공공주택·경기장·주차장·화장시설 등)의 공사 발주공고를
나라장터 Open API로 전량 수집하고, 첨부 공고문(HWP/PDF)을 파싱·LLM 추출하여 Excel DB로 정리한다.
설계 배경과 단계별 상세는 `docs/나라장터_공사비DB_자동화_울트라플랜.md` 참조. 세션별 붙여넣기용 지시문은 `PROMPTS.md`.

## 1. 준비 (한 번만)
```powershell
git clone https://github.com/seio0701/g2b_costdb.git C:\DB_WORK\g2b_costdb   # 처음 한 번
cd C:\DB_WORK\g2b_costdb                   # ★ 모든 명령은 이 폴더에서 실행 (config.yaml 이 있는 곳)
pip install -r requirements.txt
pip install pyhwp                          # 선택: HWP 폴백(hwp5txt)
pip install formulas                       # 선택: Excel 수식 오류 점검(tests/check_excel.py). 없으면 Excel 에서 직접 열어 확인
# 공공데이터포털 → 「조달청_나라장터 입찰공고정보서비스」 활용신청(자동승인) → 마이페이지에서 '일반 인증키(Decoding)' 복사
#   선택: 「조달청_나라장터 낙찰정보서비스」도 활용신청하면(같은 키) 낙찰금액·낙찰률 참고 컬럼을 함께 수집 → config.yaml api.use_awards: true
setx G2B_SERVICE_KEY "발급받은키"           # 영구 설정(새 터미널·새 Claude Code 세션부터 적용). 키를 채팅·파일에 붙여 넣지 말 것
$env:G2B_SERVICE_KEY="발급받은키"           # 지금 열려 있는 터미널에서 바로 쓰려면 이것도 실행
setx ANTHROPIC_API_KEY "..."               # S6 LLM 추출 단계에서만 필요
python -m g2b_costdb.pipeline doctor       # 파이썬·패키지·키 존재 여부(값은 안 보임)·네트워크 점검
```
`config.yaml`: 수집 기간(`period`), 경로(프로젝트 폴더 기준), 모델명, 임계값. `keywords.yaml`: 표2 검색어·변형어·제외어·분류 규칙.

## 2. 실행 순서
| 단계 | 명령 | 산출물 | API 호출 |
|---|---|---|---|
| 환경 점검 | `python -m g2b_costdb.pipeline doctor` | 콘솔 보고 | 1회(키 없이 연결 확인) |
| 필드 확인 | `python -m g2b_costdb.pipeline probe --ym 2026-08` | 응답 필드명·표본 + `config.yaml fields` 매핑 대조 결과(없는 항목 표시), 면허제한 표본, (`use_awards` 켜면) 낙찰 표본과 `[award_*]` 매핑 상태. 표본은 그 달의 첫 7일로 받는다(아래 '조회 기간 제한') | 3~6회 |
| S1 전량수집 | `python -m g2b_costdb.pipeline collect` | `data/raw/*.jsonl`, `data/notices_all.parquet`, `data/bsis_all.parquet`, (`use_awards`) `data/award_all.parquet` | 월×구간×페이지. **조회 기간 제한**: 2026-11-10 부터 이 서비스는 한 번에 7일까지만 조회되므로(그보다 길면 오류 07 '입력범위값 초과') 한 달을 7일 이하 5구간으로 나눠 조회한다(`config.yaml api.max_window_days`. 구간의 끝은 다음 구간의 시작과 같은 분이라 경계의 공고가 빠지지 않고, 두 번 온 행은 한 번만 저장) → 한 달에 공고 약 10~20회 + 기초금액 약 10~15회. 구간 하나라도 실패하면 그 달은 완료로 표시하지 않고 기존 파일도 그대로 둔다(받은 구간은 캐시에 남아 이어받는다 — 처음 받는 달은 다음 날에도, 이미 파일이 있는 달(다시 받는 달·진행 중인 달)은 같은 날 다시 실행할 때만. 다음 날에는 그 달을 처음부터 다시 받는다). 일일예산 초과 시 `[미완료]` 표시와 남은 월을 보여주며 정상 종료 → 다음날 같은 명령 |
| (점검) 받은 원문 확인 | `python -m g2b_costdb.pipeline check-raw` | 콘솔 보고: 완료 표시된 달마다 저장된 줄 수를 서버가 알려 준 건수(`data/raw/*months.json`, 없으면 응답 캐시)와 대조해 '비었거나 짧게 저장된 달'을 찾는다. `--reopen` 을 붙이면 그 달들의 완료 표시(`*done.txt`)만 지운다(원문 파일은 그대로) — 다음 `collect`(용역은 `collect --servc`)가 완료 표시 없는 달을 모두 받는다 | 0 |
| (선택) 용역 공고 | `python -m g2b_costdb.pipeline probe --servc --ym 2026-08` 로 응답·건수 확인 → `python -m g2b_costdb.pipeline collect --servc` | `data/raw/servc_YYYYMM.jsonl`, `data/servc_all.parquet` (폐기물처리 용역·건설사업관리·설계용역만 보존. 사업의 폐기물 비용·공고 완료 보조지표·공사개요 보완용) | 월 약 20~30회(7일 구간 5개 × 구간당 4~6쪽), 전 기간 약 2,000~2,900회(일일 예산 안에서 여러 날 이어받기). `probe --servc` 가 표본을 받지 못하면 조회 조건을 바꿔 가며 서버가 돌려준 오류 코드·문구를 그대로 보여 준다 |
| S2 후보탐색 | `python -m g2b_costdb.pipeline discover` | `data/notices_std.parquet`(전량 표 — `collect` 뒤에는 다시 실행: 늘어난 공고와 나중에 올라온 기초금액·낙찰 정보가 이때 들어간다), `output/facility_candidates.xlsx` (노란 셀 검수. 다시 실행해도 이전 검수 내용은 그대로, 달라진 행은 `갱신_표시` 열) | 0 |
| **검수** | Excel에서 `검수_포함여부 / 검수_시설명 / 검수_별칭 / 검수_수요기관` 수정 후 저장·닫기. `추정가격_합계` 내림차순으로 '포함'·'검토필요'부터 본다. 지자체명만 붙은 공동주택('구례군 국민임대아파트')에 단지가 여럿 섞여 있으면 `검수_시설명`에 단지·지구명을 넣거나 별칭으로 나눈다. 같은 시설이 두 행(수요기관이 다름)이면 `시설ID` 를 같게 적어 합친다 | — | — |
| S3 재검색 | `python -m g2b_costdb.pipeline research` | `data/notices_research.parquet` (전 공종 공고), 시설별 공종 분포 표. 정확한 이름으로 없으면 어절 간격을 허용한 예비 검색. 검수 행 여러 개에 **같은 시설ID** 를 적으면 한 시설로 병합(지자체·도시공사로 나뉜 같은 시설). 찾은 공고의 **다른 차수**는 공고명이 바뀌어(변경공고의 오타 수정 등) 시설 이름으로 안 잡혀도 함께 넣는다 — 뒤 차수를 놓쳐 고치기 전 금액이 실리거나 취소된 공고가 합산되지 않게(보충 건수와 최신 차수가 바뀐 공고를 출력. 보충한 행은 `차수보충 = Y` — dedup 은 이 행의 공고명(과 공고명에서 나온 공종)으로 사업을 묶지 않고, 같은 공고에서 이름으로 찾은 가장 늦은 차수의 공고명으로 묶는다. 보충한 차수의 금액·공고일시·공고종류(취소·재공고)·이전공고번호는 이름으로 찾은 변경공고와 똑같이 쓰인다) | 0 (기본). `config.yaml api.use_license_limit: true` 로 바꾸면 공고별 면허제한 조회(공고 수만큼) |
| S4 중복정리 | `python -m g2b_costdb.pipeline dedup` | `data/notices_hist.parquet`, `data/notices_latest.parquet`, `data/logs_dedup.parquet` | 0 |
| S5 첨부수집 | `python -m g2b_costdb.pipeline attach` | `data/files/`, `data/text/`, `data/texts.json`, `data/notes_attach.parquet` | 0 (파일 다운로드만, 중단 후 재실행 시 이어서. 텍스트가 없는 공고는 매번 다시 시도하고, HWP 백엔드를 나중에 설치했으면 `attach --retry-failed` 로 실패 파일이 있는 공고를 일괄 재처리. `attach --report` 는 처리 없이 요약과 텍스트 없는 공고의 원인(`data/notes_notext.parquet`)만 출력. 대표 공고가 정정·변경 차수여도 같은 공고번호의 다른 차수 첨부(원 공고문·현장설명서)를 합쳐 처리) |
| S6 LLM추출 | `python -m g2b_costdb.pipeline extract` → 견적 확인 → 아래 세 방식 중 택일 (`--limit N` 을 붙이면 건축 공종·추정가격 큰 순 N건만: 시범용. `--redo-low` 는 신뢰도 low 이거나 건축인데 연면적이 없는 기존 결과를 다시 대상에 포함) | `data/llm_docs.json`, `data/logs_verify.parquet` | Claude API(`--yes` 없이는 비용 견적만 출력) |
| (선택) 용역 연결 | `python -m g2b_costdb.pipeline link-servc` (`collect --servc` 와 `dedup` 뒤, `excel` 앞) | `data/servc_linked.parquet`, `data/logs_servc.parquet`, `output/servc_link_summary.txt`(화면 요약 사본) → `excel` 이 `08_용역공고(참고)` 시트와 05 의 `용역_○○_추정가격` 참고 열을 만든다 | 0 |
| S7 Excel | `python -m g2b_costdb.pipeline excel` | `output/공사비DB.xlsx` | 0 |

- **S6 추출 방식 세 가지** (뒤 단계는 동일하게 이어짐, 섞어 써도 됨 — 이미 추출된 공고는 건너뜀):
  | 방식 | 명령 | 특징 |
  |---|---|---|
  | 즉시 호출 | `extract --yes` | 한 건씩 바로 처리. 정가 |
  | 배치(권장) | `extract --batch --yes` 로 제출 → 나중에 `extract --batch` 로 수거 | Message Batches, **50% 할인**, 대개 1시간·최대 24시간. 제출 상태는 `data/llm_batch.json` |
  | 2차 추출(공종별 금액) | `extract --batch --yes --trades` 로 1차 재제출과 함께 제출 → `extract --batch --trades` 로 수거 (단독: `extract-trades [--yes|--batch [--yes]|--refetch|--limit N]`) | 건축·통합발주 공고의 첨부 내역서 집계표에서 공종별 금액을 읽어 04b 시트와 05 의 문서배분_*(다른 공종 공고 안에 묶인 금액의 참고 배분) 열에 반영. 입력은 집계표 후보 행만(≤20,000자)이라 건당 비용이 1차의 1/3 수준. 내역서 Excel 도 공종별 금액 표도 없는 공고는 "집계표 없음"으로 건너뜀(과금 없음). 캐시 `data/llm_trades.json`, 배치 상태 `data/llm_trades_batch.json`(청크마다 즉시 기록) |
  | 보강 추출(기타금액·면세 문구·공사개요 세부) | `extract-extra` 로 견적 확인 → `extract-extra --batch --yes` 제출 → `extract-extra --batch` 수거 (즉시: `--yes`, 시범: `--limit 30`, 공종 한정: `--only 전기,건축`). 1차 결과는 건드리지 않고 `data/llm_extra.json` 에 저장 → 01 공사개요(조경면적·건폐율·용적률·높이·주차대수·설계특이사항)와 04 기타금액ⓒ·면세 문구에 반영 | 대표 공고 전체 기준 1차 추출과 비슷한 규모(견적 출력) |
  | 파일 인수인계 | `extract --export` → `data/llm_in/<공고키>.txt` 를 Cowork·사람이 읽고 `data/llm_out/<공고키>.json` 작성 → `extract --import`(반영한 txt·json 은 `data/llm_done/` 으로 이동) | API 비용 0. 시범 검증·예외 처리용. 지시문은 `data/llm_in/README_지시문.md` |
- `discover` 를 다시 실행해도(공고를 더 수집한 뒤, 또는 규칙이 바뀐 뒤) **이전 검수 파일에 있던 행의 시설ID 와 노란 칸은 적혀 있던 그대로** 남는다(기본값과 같아 보이는 칸도 다시 계산하지 않고, 빈칸도 빈칸 그대로). 이번 후보에 없는 행도 지우지 않고 끝에 남기며, 덮어쓰기 전 파일은 같은 폴더에 `facility_candidates.이전_날짜_시각.xlsx` 로 남긴다(검수는 사본이 아니라 `facility_candidates.xlsx` 에 한다). 이름 정리 규칙이 바뀌어 시설키가 달라진 행은 그 행의 `공고명_예시` 로 다시 맞춘다. 같은 시설ID 로 합친 줄끼리의 위아래 순서도 그대로 둔다(재검색은 묶음에서 가장 위의 '포함' 줄을 대표로 쓴다). 달라진 점은 `갱신_표시` 열과 화면에 적는다 — `신규`(새 시설: 기본값 확인. 예전 공고로 새로 잡힌 후보는 그렇게 적고, 이름이 비슷하거나 이름은 같은데 수요기관 이름만 다른 기존 시설이 있으면 번호를 함께 적는다) / `확인: …`(사업유형이 달라져 기본값이 지금 값과 다름 — 값은 바꾸지 않는다) / `후보 이름 바뀜`·`시설키 바뀜` / `신규 행(같은 시설의 다른 검색어)` / `이번 후보에 없음`. **`갱신_표시` 에 글이 있는 행만 보면 된다.** 새 시설 가운데 기본값이 `포함` 인 행은 검수하지 않고 `research` 를 실행하면 그대로 DB 와 유료 추출 대상에 들어간다 — `discover` 와 `research` 가 화면에 `[주의]` 로 그 행을 적는다(확인을 마친 행은 그 행의 `갱신_표시` 칸을 지우면 알림이 사라진다). 확인하지 않은 채 `discover` 를 한 번 더 돌리면 `신규`·`확인` 표시는 `지난번: …` 으로 남는다(노란 칸을 고치거나 그 칸의 글을 지우면 사라진다). 검수 파일의 첫 줄(머리글)·시트 이름을 바꾸거나 열을 지우면, 또는 파일이 Excel 에 열려 있으면 `discover` 는 계산을 시작하기 전에 까닭을 알리고 멈춘다(검수 파일은 그대로). 검수자가 더한 열은 남지만 셀 색·메모(주석)·필터·숨김·열 너비는 새 파일에 남지 않는다(사본에는 있다). 줄을 지워 뺀 시설은 `신규` 로 다시 생기므로 지우지 말고 `제외` 로 둔다. 검수를 시작하기 전에 규칙이 바뀌어 기본값을 다시 받고 싶을 때만 `discover --recalc`(손대지 않은 칸만 새 기본값, 이번 후보에 없는 줄은 뺌) 또는 `discover --fresh`(시설ID 만 남기고 모두 새 기본값)를 쓴다 — 검수를 마친 파일에는 쓰지 않는다. `collect` 뒤에 `discover` 를 다시 돌리지 않으면 `research` 가 `[주의] 수집된 공고가 전량 표보다 N건 많습니다`(건수가 같으면 `[안내]`)라고 알린다.
- 오늘이 속한 달은 완료 표시를 하지 않고 매번 다시 받는다. 특정 달을 다시 받으려면 `data/raw/notices_done.txt`(또는 `bsis_done.txt`)에서 해당 월을 지우고 `collect` 를 실행한다(파일이 있으므로 캐시를 우회해 새로 받음).

## 4. 주요 설계 포인트
- **전량 수집 후 로컬 검색**: 키워드마다 API를 반복 호출하지 않고 월 단위로 공사 공고를 전량 내려받아 pandas에서 검색·재검색(호출량 최소화, 재분류 무제한).
- **시설 후보 단위 = (표2 분류, 검색어, 시설키, 수요기관)**: 같은 이름의 시설이 여러 지자체에 있어도 섞이지 않는다. 재검색도 `검수_수요기관`이 있으면 그 기관의 공고만 찾는다(그렇게 찾은 공고의 다른 차수는 공고번호로 따라 넣으므로 공고명·기관 표기가 바뀐 차수도 함께 실린다). 시설명이 검색어와 일반어뿐이면('영구임대아파트', '공공주택지구', '종합운동장') 수요기관의 지자체명을 앞에 붙여 '구례군 국민임대아파트'처럼 만들고, 재검색은 접두어를 뗀 패턴으로 그 수요기관 공고를 찾는다.
- **사업유형**: 신축·증축·리모델링 모두 DB 대상(유지보수만 제외). 시설 후보의 사업유형은 공고 중 하나라도 신축·증축·리모델링이면 그 유형(우선순위 신축 > 증축·리모델링 > 증축 > 리모델링)으로 두어, 유지보수 공고가 많은 시설의 본공사가 묻히지 않게 한다. 같은 시설의 신축과 리모델링은 프로젝트ID(시설ID-N/E/R/ER)로 분리 집계.
- **세부사업 분리·재발주 처리**(`works.py`, `dedup.py`): 한 시설 후보(시설ID×사업유형)에 여러 사업이 묶인 경우(예: 한 공사의 '공공주택' 후보에 3단지·16단지·A1-14BL 이 함께) 공고를 **세부사업**으로 나눠 프로젝트ID 끝에 `-01`, `-02` … 를 붙인다(05 시트의 행이 세부사업 단위가 됨, `세부사업명`·`세부사업수` 열). 기준은 공고명에서 시설명·공종어·일반어를 뺀 '구분어'(현장·건물·구간 이름)와 연도·식별 번호·공고 간격(공사 규모에 맞는 기간)이다. 세부사업 안에서는 **재공고만 제외**(02 시트 대표선정사유 `대체됨(사유)`)한다 — 같은 공고명으로 3~300일 뒤 다시 난 공고(유지관리·연간단가 공사는 180일까지 — 그보다 떨어지면 재공고 표기가 있어도 다음 회차), 공고종류·공고명에 '재공고' 가 있으면 같은 날·다음 날도, 건립·신축·증축·조성처럼 한 번 하는 공사가 같은 이름으로 1,200일 안에 다시 발주된 경우, 이름이 조금 바뀌고 금액이 거의 같은 공고, API 이전공고번호 연결. 공고명의 차수·단계 표기가 다르면('조성사업' / '조성사업(2차분)', '(1차)' / '(2차)') 재공고가 아니라 차수별 발주로 본다(단 '(2회)'·'(2차 재공고)' 는 공고 회차이고, 괄호로만 적은 '(2차)' 도 금액이 그대로이고 재공고라고 밝혔거나 120일 안에 났으면 두 번째 공고 = 재공고). 그 밖에 같은 공종의 다른 공고(기계소방/전기소방, 차수별 발주, 무대기계·정화조 같은 부대공사)는 모두 합산한다 — 06 '같은 공종 합산'·'세부사업 분리' 에서 확인. '공법·자재 선정 기술제안서 제출 안내' 처럼 공사 발주가 아닌 공고는 합산하지 않는다(`제안 안내 공고(공사 발주 아님)`, 06 '제안 안내 공고 제외' — 이름에 공법·자재·신기술·특허가 있어야 하며, 협상계약의 '제안서 제출 안내' 는 실제 발주로 본다). 금액 ±30% 변동 재발주는 경고. 예전의 '같은 공종의 최신 1건만 대표'·'소액 공고 제외' 규칙은 서로 다른 사업을 대체시키고 금액을 빠뜨려 폐기했다.
- **용역 공고 연결(`link-servc`, 참고용)**: 수집한 용역 입찰공고(설계·건설사업관리/감리·폐기물 처리)를 시설·프로젝트에 잇는다. API·LLM 호출 없음. 원칙은 '틀린 금액을 보이느니 빈칸' — 가릴 수 없는 공고는 08 시트에 까닭과 함께 `합산여부` N 으로 싣는다. **시설**: 용역 공고명에 검수된 시설 이름(별칭 포함. 띄어쓰기·괄호는 무시)이 있고, 수요기관이 그 시설 공사 공고의 수요기관과 같은 발주 주체일 것(같은 시·군·구와 그 사업소·부서, 같은 시·도 교육청, 같은 기관. 광역 이름이 바뀐 '강원도 ○○시' = '강원특별자치도 ○○시' 포함. 수요기관코드가 같으면 이름이 달라도. 공고기관은 수요기관이 빈 공고에서만 대신 본다 — 조달청이 대신 공고하는 일이 흔하다). 그 지자체의 대행 기관(도시공사·시설관리공단·건설본부 등)이 낸 공고와, 시설 이름의 어절 사이에 다른 말이 낀 공고는 '추정' 으로만 싣는다. 같은 부처·공사·교육청의 **다른 소속기관·지사·학교**가 낸 공고는 공고명에 그 프로젝트의 사업 이름이 통째로 있을 때만 더하고, 그때도 다른 현장 이름('○○지구')이 함께 있거나 사업 이름이 '시설 종류 + 건립·신축' 뿐이면 더하지 않는다(글자 그대로 같은 이름으로 낸 다른 지사의 공고는 가릴 수 없다 — 08 의 수요기관을 볼 것). **프로젝트**: 공고 시점이 맞는 프로젝트(설계: 공사 84개월 전~6개월 뒤 / 건설사업관리·감리: 48개월 전~36개월 뒤 / 폐기물: 12개월 전~48개월 뒤) 가운데 공고명에 든 사업 이름(공사 공고명에서 공종·'공사' 를 뺀 것) → 공고명의 사업유형(신축·증축·리모델링) → 공사와의 간격(설계는 공사보다 먼저, 폐기물 처리는 공사 중·뒤) 순으로 정하고, 가릴 수 없으면 프로젝트ID 를 비워 둔다(이름이 맞아도 시점이 창 밖이면 잇지 않는다). **05 참고 열**: `용역_설계_추정가격`·`용역_건설사업관리·감리_추정가격`·`용역_폐기물처리_추정가격` 은 08 시트에서 `합산여부` 가 Y 인 줄의 추정가격(부가세 제외) 합이며 **총공사비합계·㎡당 공사비에는 들어가지 않는다**. 빈칸은 '더한(Y) 공고가 없음' 이지 용역비 0 이 아니다(N 으로만 이어진 공고는 08 에 있을 수 있다). 합산여부 N 의 까닭은 08 `합산제외_까닭`: 취소·재공고로 대체된 공고(재재공고·수정/사전 공고·PQ 안내 포함. 설계·건설사업관리는 금액을 고쳐 다시 낸 공고도. 폐기물 처리의 '(1차)'·'(2차)' 는 금액이 15% 넘게 다르면 차수분으로 보아 둘 다 더한다), 여러 시설을 묶은 공고('외 2교', '○○ 및 △△ 건립 …'), 연간·단가 계약, 부대 용역(타당성·VE·설계의도 구현·공모 관리), '설계' 낱말이 없는 제안공모, 운영 폐기물(생활·음식물), 정보시스템 감리, 유지보수 성격의 공사에 딸린 용역, 어느 공사의 폐기물인지 알 수 없는 폐기물 공고, 석면·해체 공사만의 감리, 다른 시설에도 이어진 공고, 접두를 뗀 짧은 이름('주차타워')으로만 이어지고 공사와 시점이 먼 공고, 연결이 추정인 줄, 프로젝트를 정하지 못한 줄. 08 의 노란 칸(`합산여부`·`프로젝트ID`)을 고치면 05 가 따라 바뀐다(프로젝트ID 가 빈 줄은 프로젝트ID 도 적어야 한다. `excel` 을 다시 만들면 처음 값으로 돌아간다). 용역비가 공사 추정가격 합에 견주어 지나치게 크면(설계 12%·건설사업관리/감리 15%·폐기물 10% 초과) 06 에 '용역비 비율' 경고. **`dedup` 을 다시 돌렸으면 `link-servc` 도 다시 돌린다** — 프로젝트ID 의 번호가 다른 사업을 가리킬 수 있어, 오래된 연결 결과(파일 시각 또는 프로젝트의 첫 공고일이 달라진 경우)는 `excel` 이 싣지 않고 알려 준다. 용역 수집이 덜 끝났으면 `link-servc` 가 빠진 달을 [경고] 로 알린다. 규칙은 공개된 공고명 사례 358개와 실제 공사 공고명으로 만든 가상 공고로 시험했을 뿐 실제 용역 자료로 조정한 것이 아니므로, 금액을 쓰기 전에 08 시트의 공고명을 확인할 것.
- **시설 간 중복 프로젝트 표시**(`dedup.cross_facility_duplicates`): 같은 공고가 여러 시설 후보에 걸려(예: '○○공사 공공주택' 이라는 묶음 후보와 그 단지 이름의 후보) 같은 사업이 05 시트에 두 번 이상 집계되면 05 `시설간_중복` 열에 관계('같은 사업: X' / 'X 의 일부' / 'X 를 포함(n/m건)' / 'X 와 일부 겹침(n/m건)' / 'X + Y 에 나뉘어 있음')를, `중복_제외권장` 열에 뺄 행(Y)을 적는다. Y 행을 빼면 같은 공고가 두 번 합산되지 않고(서로 일부만 겹치는 프로젝트는 권장이 없어 남을 수 있다 — `dedup` 실행 요약과 06_검증로그 '시설 간 중복 프로젝트' 에 남은 건수를 적는다), 어느 프로젝트에도 남지 않는 공고도 생기지 않는다 — 여러 프로젝트의 합계·평균을 낼 때는 Y 행을 필터로 제외한다(같은 사업끼리는 세부사업으로 나뉘지 않은 더 구체적인 시설의 행을 남긴다. 일부만 겹치면 권장 없음).
- **공종 분류 우선순위**: 면허제한 업종명(선택) → 주공종명·부공종명(목록 응답의 업종명, 예: '기계설비ㆍ가스공사업') → 공고명 규칙('토목건축공사업'은 건축). 유지보수(방수·도색·교체 등) 공고는 기본 제외.
- **금액 구성·대표값(04·05 시트)**: 04 는 요청 양식 순서 `추정가격 | 부가세 | 도급자관급비 | 추정금액 계ⓐ | 관급자관급비ⓑ | 기타금액ⓒ | 금액합계` 로 채택값 수식을 두고, 금액합계는 **추정가격 기준**(추정가격+부가세+관급+기타)과 **기초금액 기준**(기초금액+관급+기타) 두 열을 함께 제시한다(05 의 총공사비합계·㎡당 공사비도 두 기준). 부가세는 API 부가세 → 문서 부가세 → 기초금액−추정가격 → 10% 가정 순(`부가세_출처`), `과세구분` 으로 면세·부분면세(조세특례제한법 제106조) 표시. 공종은 공고명 꼬리표 `(전기)`·`(통신)`·`(소방)`·`(통신설비)`·`(전기/2차분)` 도 인식하고(괄호 앞이 '소방'·'건축' 이면 그 공종: '소방(전기)공사' → 소방), 미분류 공고는 `기타` 로 두되 `공종_비고` 에 사유를 적는다. 05 `건축공종계` = 건축+기계설비+토목+조경.
- **금액 기준**: 추정가격·기초금액·관급자재는 모두 API 값이 1순위(2026-09 실제 응답에서 `presmptPrce`, `bssamt`, `govsplyAmt`, 도급자/관급자 설치 관급액 `contrctrcnstrtnGovsplyMtrlAmt`/`govcnstrtnGovsplyMtrlAmt`, `VAT`, `bdgtAmt` 확인). 문서 추출값은 API 값이 없을 때의 대체·교차검증용(단, 문서 기초금액이 추정가격의 100~110.5% 범위이면 두 경우에 계산에 쓰인다: ① API 기초금액이 없을 때 — 금액합계(기초금액 기준)이 문서 기초금액을 따른다 ② API·문서 부가세를 둘 다 쓸 수 없고 API 기초금액도 없거나 그 범위 밖일 때 — 부가세(= 문서 기초금액 − 추정가격)와 금액합계(추정가격 기준)이 문서 기초금액을 따른다). 관급 금액은 API 에 없으면 문서 값을 쓰되, 문서 값이 그 공고의 기초금액·추정가격(관급자관급액은 부가세도)·문서의 총공사금액과 같은 금액이거나 문서의 총공사금액이 두 관급액의 합과 같으면(도급액을 관급 칸으로 읽은 것) 04 에 싣지 않고 06 에 경고를 남긴다 — 빼면 문서의 총공사금액에서 더 멀어지는 값은 그대로 싣고 06 에 '그대로 실음' 경고(`extract_llm.gov_misreads`·`gov_kept`. 2026-11-21 실자료: 28건에서 71억이 더 합산돼 있었고 그중 22건은 합계가 꼭 두 배였다). 금액합계(기초금액 기준) = 기초금액 + 도급자관급 + 관급자관급 + 기타금액ⓒ, 추정가격 기준은 위 항목 참조(Excel 수식). 문서의 기초금액은 추정가격의 100~110.5% 범위일 때만, 10% 에 못 미치는 부가세라도 기초금액이 추정가격×1.1 과 맞으면(±1%) 채택하지 않는다(문서의 0·단위 오독 방어). LLM에는 금액을 힌트로 주지 않아 교차검증이 독립적이다.
- **낙찰 정보(선택, 참고 컬럼)**: 「낙찰정보서비스」 공사 낙찰 목록을 개찰일 기준 월 단위로 받아 공고번호+차수(없으면 공고번호)로 붙인다 → `02/03/04` 시트의 `낙찰금액_API`, `낙찰률_API`, `낙찰자`, `참가업체수`, `04` 의 `낙찰률(수식)`(=낙찰금액/기초금액, API 낙찰률과 대조). 같은 공고에 낙찰 행이 여럿(재개찰)이면 개찰일시가 최신인 행. **총공사비·㎡당 공사비에는 쓰지 않는다**(DB 기준은 추정가격·기초금액).
- **재공고 연결**: API 의 이전공고번호(`befBidBbancNo`)로 재공고↔원공고 관계를 확정하고, 이름 규칙으로 못 묶은 경우도 대체 처리한다.
- **교차검증**: 문서 추출 추정가격·기초금액 vs API 값(0.5% 넘으면 경고, 5% 넘으면 오류), 기초금액≈추정가격×1.1, 연면적·층수 범위, 총공사금액 구성 정합성 → `06_검증로그`. 판정은 정상/참고/경고/오류/미확인. '오류' 행의 비고에는 비율과 같은 공고의 다른 금액으로 알 수 있는 원인을 적는다(판정·숫자는 바꾸지 않는 단서). 기초금액 행: 문서 기초금액 = 추정가격×1.1 인데 API 기초금액이 다름 → 조달청 조사금액 기준·관급 포함 여부(차이가 0.75~1.35배를 벗어나면 API 기초금액 쪽 확인, API 기초금액 = API 추정가격이면 면세 여부·04 과세구분 확인, API 추정가격 + 부가세 = API 기초금액이면 API 쪽은 면세·부분면세) / 문서 기초금액 = 추정가격 + 문서 부가세(10% 가 아닌 부가세) → 문서 쪽은 면세·부분면세로 맞음. 추정가격 행: 문서 추정가격×1.1 = API 기초금액인데 API 추정가격이 맞지 않음, 또는 API 추정가격 = 문서 부가세 → API 추정가격 쪽 확인(04 의 추정가격·부가세·추정가격 기준 합계) / 두 쪽 추정가격이 같은 기초금액과 맞음(한쪽은 ×1.1, 한쪽은 + 부가세) → 과세 여부 확인. 공통: API값×1.1·÷1.1 → 부가세 포함 여부(같은 공고의 기초금액과 맞는 쪽을 보고 API 쪽인지 문서 쪽인지 적는다) / 10·100·1,000배와 1/10·1/100·1/1,000 → 자릿수·단위 / 두 금액이 같은 비율로 다름 → 문서가 다른 금액을 적음 / 그 밖 → 변경공고·다른 금액. 비고에는 04 가 어느 값을 쓰는지도 적는다: 보통 '04 는 API값 사용', 04 의 부가세·합계 가운데 문서 기초금액을 따르는 것이 있으면(위 '금액 기준' 의 ①②) 무엇이 따르는지. '복수 시설 배정'(한 공고가 여러 시설의 대표)·'최신 차수 보충'(시설 이름 검색에 잡히지 않아 공고번호로 보충한 차수가 최신인 공고 — 사업 묶음에는 이름으로 찾은 차수의 공고명을 쓰고, 금액·일정·표시 공고명·취소 여부는 최신 차수 것)은 참고.

- 낙찰정보서비스는 기본 꺼져 있음(`api.use_awards: false`). 활용신청 뒤 `true` 로 켜고 `probe` 로 End Point(`api.award_base_url`)·기간 조회 파라미터(`api.award_query`)·필드 매핑(`fields.award_*`)을 확인한다. 실제 응답 필드명은 아직 미확인(2026-09-09 기준 추정값, 후보 이름을 자동 탐색). 수집 실패(20/30) 시 공고·기초금액 수집은 유지되고 안내만 출력된다.
- 첨부 URL 은 `https://www.g2b.go.kr/pn/pnp/pnpe/UntyAtchFile/downloadFile.do?...` 형식이며, 로그인 페이지가 돌아오면 `07_추출노트`에 'HTML 응답' 실패로 기록된다(수동 다운로드 후 `data/files/<공고번호>/` 에 넣고 `attach` 재실행).
- HWP 파서: HWP 5.0 규격(olefile+zlib 레코드) 기반이며 실제 공고문으로 첫 실행 시 확인 필요. 실패 시 `hwp5txt`(pyhwp) → Windows 한컴 COM 순으로 폴백. 배포용(DRM)·암호 문서는 수동 처리.
- 규모: 2019-01~2026-09 전량은 공고 약 129만 건·기초금액 약 103만 건(2026-09-10 수집). `discover` 는 필요한 컬럼만 읽어 처리하며 합성 데이터 기준 수 분 소요(메모리 약 3~4 GB). `notices_std.parquet` 는 전량 표준화본이므로 수백 MB 가 될 수 있다.
- 스캔 PDF는 `pytesseract`+`pdf2image` 설치 시 OCR. 연면적이 공고문에 없으면 현장설명서·설계설명서를 함께 파싱해도 공란일 수 있음(경고 기록).
- LH 자체 조달(ebid.lh.or.kr) 발주분은 나라장터 API 범위 밖.
